## 需求描述

### 背景

- **业务问题**：大众消费者对不认识的中草药容易误采误食，网络信息鱼龙混杂难辨真伪；从业者人工鉴定依赖个人经验、纸质药典检索繁琐；市面识花类 App 只认鲜植物、识别范围有限，且结果缺乏权威依据、不含药用安全提示。本项目通过多模态交互（图像 + 文本 + 语音）提供"识别 + 用药安全 + 专业信息"的一体化解决方案。
- **目标用户**：双核心画像——① 中医药专业/从业者（中医师、执业药师、药材采购/验收/质检人员、院校师生）；② 消费者（养生爱好者、户外人群、家庭照护者、普通患者家属）。
- **价值主张**：
  - **识别**：识别鲜植物与常见中草药，快速给出识别结果；
  - **安全**：面向大众突出用药安全警示与免责声明，降低误食/误用风险；
  - **专业**：面向从业者提供真伪、品相鉴定与药典信息比对能力；
  - **多模态**：图文 + 语音交互，降低使用门槛。
- **项目背景**：大学生暑期实训选题；产品形态为 Web/H5，移动优先 + 桌面端大屏适配（响应式）。

### 功能概述

> **项目口径变更说明（两周演示版）**：本项目为大学生暑期实训选题，实际开发周期为 **2 周**，不做真实上线，交付目标为结项演示汇报。因此功能范围按「两周演示版」重新划分——多模态问答由原 P1 提升为**必做核心功能**（支撑项目名），真伪鉴定/品相评估等专业能力与 P2 远期项暂不纳入两周范围。原始 P0/P1/P2 三级优先级定义保留于需求文档 v0.4，供远期迭代参考。

- **核心功能（两周演示版，按「做 / 降级 / 砍掉」三档重排）**：
  - **必做（核心闭环 + 创新点 + 多模态，共 13 项）**：
    - 识别主流程：拍照识别、相册上传识别、识别结果展示（名称/置信度/相似对比）；
    - **自训练本地模型识别（创新点，本实训实际完成）**：PyTorch 自训练药材分类模型作为本地主识别通道，低置信回退百度、再兜 Mock；
    - 安全合规：易混淆高危辨析提示、用药安全提示与医疗免责声明、毒性/禁用高危警示；
    - 信息查询：功效主治/性味归经查询、用法用量/禁忌/毒性查询；
    - 多模态交互（**项目名支撑，必做**）：多模态图文+语音问答（结果页追问）、语音输入；
    - 隐私合规：首次授权与隐私说明；
  - **降级（简化实现，3 项）**：识别历史与收藏、注册登录（降级为浏览器本地存储，不接真实后端账户体系）、拍摄部位引导（首次简单引导文案即可）；
  - **砍掉（口头提及 / 远期规划，其余 9 项）**：真伪鉴定、品相评估、药典比对、单味药材百科、多图/批量识别、离线识别、结果分享、社区/专家鉴定、鉴定报告导出 PDF、配伍/方剂查询、药材行情参考、国际化、开放 API、AR 识别、健康养生建议。
- **创新点（区别于形色等纯识花应用）**：
  1. **「识别 + 用药安全」一体化**：识别结果与安全等级三色联动（普通/慎用/毒性）+ 高危强制警示页绑定，识别即给安全结论，而非仅给出「这是什么植物」；
  2. **分层信息卡（白话科普 / 专业药典）**：同一识别结果双视角分层展示，服务消费者与从业者双画像用户；
  3. **高危易混淆药材强制辨析**：金银花 vs 断肠草、乌头类等，采用「宁严勿松」策略，可疑即触发不可跳过的强制警示页，防误食误用；
  4. **自训练本地模型识别（本项目自主训练）**：采集真实中草药数据集，用 PyTorch（ResNet50 迁移学习，GPU 训练）自训练一个药材图像分类模型，作为**本地主识别通道**（channel=local），摆脱对单一第三方 API 的依赖；本地置信度低于阈值时自动回退百度植物识别、再兜底 Mock，兼顾**识别自主可控**与**针对本项目药材库的识别准确率提升**。
  > 注：多模态交互本身为项目名的功能完整性支撑，属必做功能项，不单独列为创新点；自训练本地模型为额外创新点，与多模态问答共同构成演示亮点。
- **功能边界（两周演示版）**：
  - **包含**：识别主流程闭环（含**自训练本地模型主通道**）+ 安全合规底线 + 基本信息查询 + 历史记录（本地化）+ 多模态问答；
  - **不包含（两周内不做，口头提及/远期）**：真伪/品相鉴定、药典比对、单味药材百科、多图批量识别、离线识别、结果分享、社区/专家鉴定、报告导出、行情、国际化、开放 API、AR、养生建议；
  - **产品边界（红线）**：任何识别/查询结果不构成诊断或处方建议；不提供药品交易/导购功能；不生成健康养生个性化建议。
- **用户场景**：
  - 场景一（消费者）：野外/市场/家中拍下不认识的中草药 → 识别 → 查看功效、用法用量、禁忌与安全警示（高危品种强制确认）→ 结果页语音/文本追问；
  - 场景二（从业者）：药材入库验收拍摄常见中草药 → 识别 → 查看药典级专业信息（简版/专业版分层）；
  - 场景三（答辩/演示）：桌面端大屏分栏展示识别结果页，左栏图片对比、右栏信息卡与警示区，并现场演示「识别 → 追问」多模态闭环。

### 详细需求

#### 输入/输出规格

| 功能 | 输入 | 输出 |
| --- | --- | --- |
| 拍照/相册识别 | 图片（≤1MB，前端压缩后上传） | 药材名称 + 置信度 + 相似品种对比 + 分层信息卡（白话/专业）+ 安全警示区 |
| 信息查询 | 识别结果 / 百科搜索关键字 | 功效主治、性味归经、用法用量、禁忌人群、毒性/副作用（分层展示） |
| 安全警示 | 识别结果的药材安全等级 | 普通/慎用/毒性三级提示；高危/易混淆品种触发强制全屏确认页 |
| 注册登录 | 手机号/账号 + 密码（或第三方授权） | 登录态，支撑历史/收藏/隐私设置 |
| 历史/收藏 | 用户身份 + 识别记录 | 按时间分组的识别历史、收藏列表（可删除/清除） |
| 隐私授权 | 首次使用相机/相册/麦克风授权 | 授权说明弹窗，记录授权状态 |

#### 用户交互流程

1. **识别主流程**：打开首页 → 选择拍照/上传 → 拍摄部位引导（首次）→ 识别中（≤3s）→ 结果页；高危/易混淆 → 强制全屏警示确认页（不可跳过）→ 确认后进入结果页；
2. **多模态问答流程（结果页追问）**：结果页 → 点击「追问」入口 → 文本输入或语音（Web Speech API 转文字）→ Qwen 结合识别结果上下文生成回答 → 附免责声明展示 → 支持继续追问；
3. **首次合规流程**：首次打开 → 隐私授权说明（相机/相册/麦克风 + 数据用途）→ 同意后进入首页；
4. **历史/收藏**：结果页收藏 → 历史页查看/重新识别/删除。

#### 数据需求与验证规则

- **药材知识库**：每条记录含药材名称、基原、性味归经、功效主治、用法用量、禁忌、毒性/副作用、**安全等级字段（普通/慎用/毒性，必填）**、相似易混淆品种、图片库、数据来源标注；
- **识别结果**：名称、置信度（0-1）、触发通道（local 自训练模型 / baidu / mock）、时间戳、关联药材 ID；
- **用户数据**：账号、识别历史、收藏列表、授权状态；历史记录默认本地可见，提供"清除历史"能力；
- **验证规则**：置信度低于阈值时不直接给结论，降级为"相似品种列表"并引导重拍；知识库高危字段上线前需人工/专家复核。

#### 边界情况与错误处理（补全项）

| 场景 | 处理策略 |
| --- | --- |
| 图片模糊/反光/多主体 | 前端提示重拍，识别通道返回低置信度 → 降级为相似品种列表 + 引导"换个角度/部位" |
| 百度无法识别该药材 | 返回"暂未收录" + 建议联系反馈 |
| 识别失败 / 后端异常 | 友好错误提示 + 重试按钮，不展示任何推测性结论 |
| 无网络 / 网络超时 | 提示网络异常（P1 离线识别上线前）；已有历史记录仍可本地查看 |
| LLM 问答不可用/超时 | 降级为知识库结构化信息展示，不阻断主流程 |
| 语音识别失败 | 提示改用文本输入；语音按钮置灰并说明需联网 + Chrome 系浏览器 |
| 毒性/高危品种误判 | 高危判定采用**宁严勿松**策略，可疑即触发警示确认页；结果页始终附免责声明 |
| 首次授权被拒绝 | 功能降级提示（无法拍照/上传），引导至设置页开启；不强制阻断浏览百科 |
| 并发/大图上传 | 前端压缩 ≤1MB，服务端限流与超时控制 |

#### 多模态问答（结果页追问）UI 结构

> 追问入口嵌入现有识别结果页 `ResultView.vue`，复用现有绿色主题（主色 `#2E7D52`）与卡片式设计语言，不新建独立页面。

- **入口**：结果页分层信息卡下方，放置「追问」卡片——标题「对这味药还有什么想了解？」+ 一句示例问题（如「它有什么禁忌？」），点击展开问答区；
- **问答区（聊天气泡式）**：
  - 用户消息（右对齐、绿色底 `#2E7D52` 白字）；AI 回答（左对齐、白底描边气泡），每条回答底部附小字免责声明「以上内容仅供参考，不构成诊断或处方」；
  - 空态：无对话时显示 2-3 个「常见问题」快捷标签（怎么用 / 有什么禁忌 / 毒性如何），点击即发送；
- **输入栏（底部固定）**：文本框 + 语音按钮（`van-icon` 麦克风图标），语音输入时显示录音态动效；加载中显示「思考中…」占位；
- **降级态**：Qwen 不可用时，回答气泡显示知识库结构化信息（功效/用法/禁忌摘要），并标注「已切换至本地知识库展示」；
- **状态覆盖**：空态 / 加载态 / 成功态 / 降级态 / 语音失败提示态，均需明确呈现。

## 设计决策

### 技术方案

- **架构选择**：前后端分离 B/S 架构。前端 Vue 3 + Vant + Tailwind CSS（移动优先、响应式）；后端 Python FastAPI 提供识别代理、知识库查询、历史记录接口；多模态交互接入通义千问（Qwen）API。
- **关键组件**：
  - 前端：首页（识别入口）、识别结果页、百科详情页、历史记录页、个人中心、高危警示页（强制全屏）、拍摄部位引导、隐私授权弹窗、多模态问答输入组件；
  - 后端：识别调度（本地优先 + 百度兜底 + Mock 保底）、置信度阈值判定、知识库匹配、安全警示判定、历史记录服务、LLM 问答代理；
  - 识别引擎：**本地自训练模型（PyTorch ResNet50）主通道 + 百度植物识别 API 兜底 + Mock 演示数据保底**；本地模型通过 `training/train.py` 训练，产物 `model.pth` + `classes.txt` 供后端 `LocalRecognizer` 加载推理；
  - 语音输入（**必做**）：Web Speech API（免费，需联网 + Chrome 系浏览器）；
- **数据存储**：SQLite（起步）→ MySQL；表：users、herbs（药材知识库）、recognition_history、favorites、privacy_consents。
- **接口设计（概要）**：
  - `POST /api/recognize`：上传图片 → 识别结果（含通道、置信度、安全等级、相似品种、分层信息）；
  - `GET /api/herbs/{id}`：药材知识库详情；
  - `GET /api/search/herbs`：百科搜索；
  - `POST /api/qa`（**必做**）：多模态问答（识别结果上下文 + 文本/语音，Qwen 真实调用，失败回退知识库结构化展示）；
  - `POST /api/auth/*`：注册/登录；
  - `GET/POST/DELETE /api/history`、`/api/favorites`：历史与收藏。

### 约束条件

- **性能要求**：识别接口目标 ≤3s（含网络）；图片前端压缩后上传 ≤1MB；结果页首屏渲染 ≤2s。
- **兼容性**：响应式断点 移动端 ≤375px / 平板 768px / 桌面 ≥1024px；桌面端最大阅读宽度约 1200px；主流移动浏览器（iOS Safari / Android Chrome / 微信内置浏览器）可用；支持 PWA 安装与缓存（P1 离线能力前置）。
- **安全性**：用户上传图片仅用于本次识别请求，前端完成后即清除，服务端不持久化原始图片（或明确保留期限并在隐私说明中告知）；医疗免责声明为全流程强制项；高危警示不可跳过；接口限流与鉴权。
- **可扩展性**：识别范围随百度植物识别 API 能力与本地知识库扩展；预留 P1/P2 功能扩展点（问答、鉴定、导出）。

### 风险评估

- **技术风险**：
  1. 百度植物识别对部分药材识别准确率不足 → 缓解：自训练本地模型主通道提升针对本项目药材库的准确率；低置信度时降级为相似品种列表并引导重拍；宁严勿松的高危判定策略兜底；
  2. Qwen 多模态能力与免费额度不确定 → 缓解：问答为两周必做项，开发早期即验证 vision 能力；问答不可用时降级为知识库结构化展示，不阻塞演示；
  3. 语音转写准确率不足（Web Speech API 需联网 + Chrome 系）→ 缓解：演示使用 Chrome 浏览器并联网；识别失败时提示改用文本输入；
  4. 自训练模型识别准确率有限 / 过拟合（本模型实测验证集约 77.8%）→ 缓解：本地低置信时自动回退百度兜底；易混淆药材由高危强制辨析机制补强；后续可通过扩充数据、调参、换骨干网络提升。
- **依赖风险**：
  1. 百度植物识别 API 计费与调用限制变动 → 缓解：以免费额度起步，监控成本，识别失败回退 Mock 演示数据；
  2. 第三方 API 服务不可用 → 缓解：识别失败重试与降级提示，链路不中断。
- **进度风险**：
  1. 实训周期压缩为两周 → 缓解：聚焦「识别闭环 + 多模态问答 + 合规底线」一条主线，专业鉴定/百科等远期项暂缓；
  2. 知识库内容整理与合规审核工作量大 → 缓解：优先 P0 所需字段，高风险字段专家复核后上线；
  3. 演示环境稳定性（本地+内网穿透）→ 缓解：预留云服务器方案，答辩前联调验证。

## 验收标准

> 验收对象为 **两周演示版功能集**（必做核心闭环 + 多模态问答 + 合规底线）。真伪鉴定/品相评估/药典比对/百科等 P1 专业能力与 P2 远期项不在本次验收范围。

### 功能验收（两周演示版共 13 项）

- [ ] **F1 拍照识别**：移动端可调用相机拍照，识别请求成功发出并返回结果；识别接口响应 ≤3s（含网络）；图片自动压缩至 ≤1MB
- [ ] **F2 相册上传识别**：支持从相册选择图片上传识别，与拍照识别同等处理链路
- [ ] **F3 识别结果展示**：结果页展示药材名称、置信度、相似品种对比图；置信度低于阈值时降级为"相似品种列表"而非直接结论，并引导重拍
- [ ] **F4 易混淆/高危辨析提示**：对金银花 vs 断肠草、乌头类等高危品种识别结果，展示辨析提示并触发强制全屏警示确认页（不可跳过，无关闭入口）
- [ ] **F5 功效主治/性味归经查询**：结果页展示分层信息卡——白话科普卡（消费者可读懂）与专业药典卡（基原、性味归经、功效主治），数据来源可标注
- [ ] **F6 用法用量/禁忌/毒性查询**：信息卡包含用法用量、禁忌人群、毒性/副作用字段；高风险字段（用法用量、毒性）上线前经人工/专家复核并留痕
- [ ] **F7 用药安全提示与免责声明**：所有结果页底部固定显示免责声明条："结果仅供参考，不构成诊断或处方，如有不适请咨询执业医师/药师"；任何页面不出现诊断/处方性表述
- [ ] **F8 毒性/禁用高危警示**：知识库安全等级字段（普通/慎用/毒性）联动 UI 警示；毒性药材识别即触发强警示（红/橙高对比配色 + 警示图标）
- [ ] **F9 识别历史与收藏（降级实现）**：识别历史按时间分组展示，支持重新识别、删除；支持结果收藏；历史/收藏数据存于浏览器本地存储
- [ ] **F10 注册登录（降级实现）**：登录态存于浏览器本地存储，支撑历史/收藏；不接真实后端账户体系
- [ ] **F11 首次授权与隐私说明**：首次打开弹窗说明相机/相册/麦克风权限用途及图片数据使用规则；拒绝授权时功能降级提示而非强制阻断；隐私说明文案合规可查
- [ ] **F12 多模态图文+语音问答**：识别结果页提供追问入口，输入文本/语音问题后，Qwen 结合识别结果上下文生成回答，回答附免责声明；Qwen 不可用时降级为知识库结构化展示，不阻断主流程
- [ ] **F13 语音输入**：结果页支持语音转文字输入提问（Web Speech API，需联网 + Chrome 系浏览器）；识别失败时提示改用文本输入

- [ ] **Q1 代码质量**：前后端代码遵循统一风格规范，后端提供类型标注，关键模块有注释；无未处理的阻塞性异常

- [ ] **U3 文档交付**：本 PRD、初版需求文档、部署说明、演示脚本齐全；识别范围与准确率以实际验证结果如实标注
- [ ] **U4 合规收口**：评审确认无诊断/处方风险表述；毒性药材分级警示策略经指导教师/药师确认

**目标**：环境准备 + 打通识别主链路 + 验证 API 额度
- [ ] 搭建前端（Vue 3 + Vant + Tailwind）与后端（FastAPI）项目骨架，确定代码仓库与协作方式
- [ ] 申请并验证百度植物识别 API 免费额度，跑通最小识别 demo
- [ ] 申请并验证通义千问（Qwen）API 免费额度与多模态（vision）能力（**多模态为必做，需尽早验证**）
- [ ] 打通「图片 → 后端 → 识别 → 结果」最小 demo（含 Mock 兜底）
- **交付物**：可运行的"图片 → 识别 → 结果"最小 demo
- **时间**：约 3 天

### 阶段2：核心开发（第 1 周后半 – 第 2 周前半，约 5 天）
**目标**：实现两周演示版必做功能（识别闭环 + 多模态问答 + 合规底线）
- [ ] 前端：首页 + 识别结果页 + 高危警示页 + 隐私授权弹窗 + 响应式适配
