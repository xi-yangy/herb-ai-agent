## 1. 初验定位与时长分配

- **一句话定位**：一款「拍照识别 + 用药安全提示 + 多模态问答」的中草药识别智能体；
- **演示总时长**：**约 3 分钟**（主线 190 秒，第五幕扩展页展示可再超时 10–20 秒，以演示完整为准）；答辩 2 分钟（预判 3–7 个高频问题，按现场取舍，见第 3 节）；

  - 百科 / 历史 / 我的等扩展页已完整上线，第五幕收尾逐页点开、简要介绍各页核心点（超时一点不碍事）。

## 2. 三分钟演示主线（五幕走位与台词）

> 说明：`【操作】` 为现场动作，「台词」为可照念的话术（可据自己语言微调，**关键数字与合规表述不建议改动**）。每幕台词按对应时长估算语速（约 4–5 字/秒），照念即可控时。

### 第一幕：开场（15 秒）

- 【操作】停留在首页 `HomeView`，大屏可见品牌区「灵草 · 多模态中草药识别」与三个技术亮点标签。
- 「台词」：
  > 这是我们团队做的「多模态中草药图像识别智能体」。核心是**拍照识别**：一张照片，几秒给出药材名称、功效与安全等级。在这个核心之上，我们做了两个亮点：**高危药材强制警示、图文语音多模态问答**。

### 第二幕：识别主流程（50 秒）

- 【操作】点击「相册上传」，选择一张**在库普通药材**演示图（如黄芪）→ 识别 loading → 自动跳转结果页 `ResultView`。
- 【操作】手指指向**安全等级色条**（普通 = 绿色）与药材卡片（名称、置信度、识别通道），再向下滑动示意「白话科普 / 专业药典」分层卡。
- 「台词」：
  > 现在演示核心流程。上传一张黄芪照片，几秒出结果——左上角绿色标签代表普通药材，同时给出置信度和识别通道。这里特别说明：识别采用「**本地自训练模型优先、识别不出时自动回退百度植物识别**」的两段式调度——本地模型是我们用 ResNet50 在自建药材库上训练的主通道，减少对单一第三方 API 的依赖；万一本地模型判不准，百度识别会兜底，保证链路不断。同一个结果我们还做了分层展示：白话科普卡面向普通消费者，专业药典卡面向从业者。

### 第三幕：高危强制警示（45 秒）★ 演示亮点

- 【操作】返回首页，上传一张**毒性药材**图片（如白矾，知识库 `safety_level=毒性`，且在本地 ResNet50 模型类别内，识别走 local 主通道）→ 识别结果自动跳转全屏警示页 `WarningGateView`。
- 【操作】刻意演示「无关闭入口」：页面只有「我已了解风险」一个按钮，无返回、无 X、无跳过。
- 【操作】点击「我已了解风险」→ 进入结果页，指向顶部**鉴别防雷警报卡**（本药材 vs 易混淆高危品种辨析 + 警示语）。
- 「台词」：
  > 这是本项目最重要的安全设计：**高危判定宁严勿松**。上传白矾——毒性药材——识别后直接弹全屏警示。大家注意，这个页面**没有关闭按钮、没有跳过入口**，用户必须确认已知晓风险才能进入结果。以白矾为例，药典列为有毒，内服须严格控制用量，警示页直接给出毒性说明和"遵医嘱、切勿自行服用"的提醒。结果页顶部还有防雷警报卡，把白矾和它的煅制品枯矾做外观、用法对比辨析。这个警示逻辑上线前会经药师复核。

### 第四幕：多模态问答 + 语音输入（50 秒）★ 演示亮点

- 【操作】在结果页滚动到问答区 `QaPanel`，先点快捷标签「有什么禁忌」→ 展示 Qwen 回答气泡 + 底部免责声明。
- 【操作】点击麦克风按钮 → 用语音问「这味药和什么容易混淆？」→ 语音转文字上屏 → 发送 → 展示回答。
- 「台词」：
  > 结果页还支持**多模态追问**。点这个快捷标签问一句"有什么禁忌"，回答由通义千问结合当前识别结果生成，你上传的那张图也会作为上下文一起参考，做图文联合问答；同时自动附带"仅供参考，不构成诊断或处方"的免责声明。再试一下语音：直接说"这味药和什么容易混淆"——语音走浏览器原生的 Web Speech API，用 Chrome 直接可用、免费、无需额外 SDK。如果 AI 不可用，系统会自动降级为**本地知识库的结构化展示**并标注提示，保证演示链路不断。

### 第五幕：收尾 + 扩展页展示（约 30 秒）

- 【操作】回到首页，依次点开底部「百科 / 历史 / 我的」三个入口，逐页简要介绍核心点：
  - **百科**：进入 `HerbView` 药材百科，划过顶部**分类胶囊**（按部位分类、标注安全等级）与**搜索框**（按药名/性味/功效搜），随机点开一条（如黄芪）进 `HerbDetailView` 详情页，指向功效 / 用法 / 禁忌 / 毒性 / 易混淆等完整字段；
  - **历史**：返回 → 进入 `HistoryView` 识别历史，指向「记录你的每一次识别」的自动留存列表（含原图缩略），点开一条回看当初上传的原图与识别结果；
  - **我的**：进入 `MineView`，指向**登录同步**（历史与收藏随账号同步）、**我的收藏**与**隐私与授权**（相机 / 相册 / 麦克风开关管理）。
- 「台词」：
  > 总结一下：**识别给结论、安全给警示、问答给延伸**——我们用多模态的方式，把"这是什么药"和"怎么安全用"串成一条完整链路。最后过一遍三个扩展页：百科页收录全部在库药材、按部位分类、可搜索，点开任意一条就是完整的功效、禁忌、毒性字段；历史页自动记录每一次识别，点进去能回看当时上传的原图和结果；我的页支持登录后同步历史与收藏，还能在"隐私与授权"里管理相机和麦克风权限。功能都做全了。后续我们会继续扩充药材库、迭代识别模型，让安全提醒更场景化。演示到这里，欢迎老师提问。
- 备注：本幕允许**超时 10–20 秒**（逐页展示核心点），以演示完整为准，无需刻意压缩。

## 3. 两分钟答辩要点（预判高频问题）

> 按项目**实测口径**回答，未验证项如实说明，不引用厂商自述作承诺。每个应答约 30–45 秒，2 分钟约能答 2–3 题，优先接好前两问。

| 可能的问题 | 精炼应答（30–45 秒） |
| --- | --- |
| **识别准确率多少？** | 本地自训练模型在验证集实测约 **77.8%**，如实标注、未虚标。为弥补单模型局限，我们采用「本地自训练模型优先、识别不出时自动回退百度植物识别」的两段式调度，页面会显示实际命中的通道和置信度。 |
| **为什么要自训练模型？** | 三个原因：一是摆脱对单一第三方 API 的依赖，识别自主可控；二是针对自建药材库做迁移学习（ResNet50 预训练权重微调），提升在库药材的针对性识别；三是作为实训创新点，走通了「数据采集 → 训练 → 部署 → 识别」完整闭环。 |
| **三通道怎么协同？** | 调度顺序：本地模型优先，低置信（0.75 以下）或未启用时回退百度植物识别。第三层是开发/演示用的保底数据，**正常演示几乎不会触发**，只在本地和百度都不可用（如断网）时兜底，保证演示不中断。每次识别结果都标注实际命中的通道，页面可见可查。 |
| **Qwen 不可用怎么办？** | 问答超时（默认 30s）或未配置凭证时自动降级为知识库结构化展示，回答带 fallback 标记并提示「已切换至本地知识库展示」，不报错、不中断，识别主流程完全不受影响。 |
| **数据与隐私怎么保证？** | 用户上传图片仅用于本次识别，前端完成后即清除，服务端不持久化原始图片；首次使用有权限说明弹窗，可拒绝并降级（拒绝相机切相册）；全流程固定免责声明，高危警示无跳过入口，知识库高风险字段上线前经人工复核。 |
| **遇到过哪些难点？怎么解决？** | 主要四方面：一是自建药材库数据采集与标注工作量大，按部位分批拍摄 + 知识库字段对齐校验；二是本地模型准确率有上限，用「置信度 + 相邻类别概率差」**双阈值拒识**（0.75 / 0.15），不确定就回退百度，宁可不猜也不给错结论；三是半夏、附子等高危药材不在本地模型类别内，靠百度兜底 + 高危强制警示双保险；四是语音在境内部分环境受限，统一用 Chrome/Edge 原生 Web Speech 并保留文本输入兜底。 |
| **总结与展望？** | 总结一句话：**识别给结论、安全给警示、问答给延伸**，形成完整闭环。展望四点：一是扩充药材库、引入配伍禁忌与煎服/饮食注意事项等权威字段；二是迭代训练提升本地模型准确率与类别覆盖，逐步降低对第三方 API 依赖；三是把安全警示扩展为用药提醒、孕妇/过敏禁忌等场景化提示；四是打磨移动端 + 桌面投屏的跨端体验并做真实用户评测。 |

## 4. 今晚演练 Checklist（初验前一天执行）

### 4.1 环境启动与就绪

- [ ] 后端：以**系统 Python** 后台启动（`Start-Process -FilePath "python" -ArgumentList "run.py" -WorkingDirectory "d:\CodeBuddy\herb-ai-agent\backend" ...`，stdout/stderr 重定向日志），**禁用 `.venv`**；
- [ ] 确认后端日志出现「**本地模型已加载（N 类，设备 cuda/cpu）**」；
- [ ] **懒加载预热**：本地模型在首次识别时才加载（需数秒），正式演示前先跑一次识别冒烟，让模型完成加载，避免现场首图卡顿；
- [ ] 前端：`cd d:\CodeBuddy\herb-ai-agent\frontend` 后 `npm run dev:raw`（勿用裸 `npm run dev`）；
- [ ] 健康检查：`curl.exe -s -o NUL -w "HTTP %{http_code}" http://localhost:5173` 与 `http://localhost:8001/api/health` 均返回 200；
- [ ] 演示浏览器为 **Chrome / Edge**（语音输入需要），已允许麦克风权限。

### 4.2 主链路冒烟（本地→百度识别链路 + 亮点验证）

- [ ] 识别一张在库药材图 → 结果 `channel=local`；
- [ ] 毒性药材图（如白矾）→ 触发全屏警示，确认**无跳过入口**；
- [ ] 易混淆品种图（如金银花）→ 结果页出现「易与断肠草混淆」防雷警报卡（可选）；
- [ ] 结果页追问一句 → 返回 Qwen 真实回答 + 免责声明；
- [ ] 语音问一句 → 语音转文字上屏并成功回答；
- [ ] 可选：临时关闭 Qwen 或断网，验证自动降级为知识库展示不报错。

### 4.3 演示图片物料清单

- [ ] ① 在库**普通药材**（如黄芪）——第二幕主链路；
- [ ] ② **毒性药材**（如白矾，`safety_level=毒性`，且在本地模型类别内走 local 通道）——第三幕强制警示；
- [ ] ③ **易混淆品种**（如金银花）——防雷警报卡演示（可选，时间富余时加）；
- [ ] ④ 低置信/陌生图（可选）——「低置信降级 + 引导重拍」应急演示。
- 建议：图片提前放入相册/桌面随手可及的位置；若现场可实拍，第二幕改用**相机拍照**更真实。

### 4.4 时间彩排

- [ ] 按第 2 节五幕完整走 2–3 遍，全程计时；前四幕控在约 160 秒内，第五幕扩展页展示允许超时 10–20 秒；
- [ ] 每幕台词熟读一遍，控时不足时优先保第三、四幕两个亮点；
- [ ] 答辩预演：请队友/同学按第 3 节随机抽 2–3 问模拟。

### 4.5 突发预案备忘（完整版见结项演示脚本第 5 节）

| 故障场景 | 现场处理 / 话术 |
| --- | --- |
| Qwen 超时 / 不可用 | 不做操作，等降级展示：「AI 问答不可用，我们自动切换到了本地知识库的结构化展示，不影响识别主流程——这是我们的降级设计。」 |
| 识别显示 `channel=baidu` | 多半是用了 `.venv` 启动后端；话术：「当前是百度兜底通道，本地模型依赖的 torch 只装在系统 Python——这也正好展示了容错设计。」 |
| 语音按钮置灰 / 麦克风被拦 | 提示改用文本输入，点快捷标签继续演示问答能力。 |
| 断网 / 后端不可达 | 首页会提示后端离线；改用 mock 演示或演示已打开的页面：「系统对异常做了兜底，识别失败会回退演示数据，链路不中断。」 |
| 图片拍糊 / 低置信度 | 走「低置信度降级」页：相似品种列表 + 重新拍摄引导，避免误导。 |

## 6. 附录：各模块技术栈一览（答辩速查）

> 前后端分离：Vue 3 前端（Vite） + FastAPI 后端 + SQLite 数据库；本地 PyTorch 模型推理 + 百度植物识别 API 兜底 + 通义千问多模态问答。**一句话口径**：全栈轻依赖——外部调用全部走标准库 urllib，不引重 SDK，整个项目「小而全、可落地」。

### 6.1 前端

| 模块 | 技术 |
| --- | --- |
| 框架 / 构建 | Vue 3.5（组合式 API）+ Vite 6 + @vitejs/plugin-vue |
| UI | Vant 4（移动端组件库）+ Tailwind CSS 3 |
| 状态 / 路由 | Pinia 2 + Vue Router 4 |
| HTTP | Axios（统一 `/api` 前缀，Vite 代理转发） |
| 语音 | 浏览器原生 Web Speech API：STT 语音输入（SpeechRecognition）+ TTS 语音朗读（speechSynthesis），零 SDK 依赖 |
| 本地图片存储 | IndexedDB（识别原图仅存本机、供历史回看，服务端不落盘） |
| 离线能力 | vite-plugin-pwa |

### 6.2 后端

| 模块 | 技术 |
| --- | --- |
| 框架 | FastAPI 0.115 + Uvicorn，Pydantic 2 参数校验，CORS 中间件 |
| ORM / 存储 | SQLAlchemy 2.0 + SQLite（连接串可迁 MySQL） |
| 路由 | 8 个模块：health / recognize / herbs（百科）/ history / favorites / auth / privacy（隐私授权）/ qa |
| 认证 | 标准库自研：PBKDF2-HMAC-SHA256 密码哈希 + HMAC-SHA256 签名 token（HTTPBearer 鉴权），不引 passlib / jose |
| 静态资源 | FastAPI StaticFiles 挂载药材示例图 |

### 6.3 识别模块（核心）

| 模块 | 技术 |
| --- | --- |
| 本地自训练模型 | PyTorch + torchvision，ResNet50 骨干 + 迁移学习（fc 换成 93 类），懒加载单例、CPU/CUDA 自适应 |
| 推理管线 | Resize(256)→CenterCrop(224)→ImageNet 归一化 → softmax → top-k |
| 拒识算法 | 置信度 0.75 + 相邻类别概率差 0.15 双阈值，不确定就回退百度 |
| 百度兜底 | OAuth2 client_credentials 取 token + REST 植物识别接口，标准库 urllib 直连 |
| 知识库匹配 | 名称双向归一化：去/补后缀、别名整词匹配、受限包含匹配（防「人参果」误中「人参」） |
| 调度器 | 本地→百度→mock 三级降级，结果标注真实命中通道 |

### 6.4 问答模块

| 模块 | 技术 |
| --- | --- |
| 模型 | 通义千问 OpenAI 兼容接口：qwen-turbo（纯文本）+ qwen-vl-plus（视觉图文） |
| 降级链 | 视觉图文问答 → 纯文本上下文问答 → 本地知识库结构化摘要（fallback 标记），均 urllib 直连 |
| 合规 | 系统提示约束「非诊断/非处方、高危药材强调遵医嘱」 |

### 6.5 数据层

| 模块 | 技术 |
| --- | --- |
| 知识库 | SQLite 存 172 味中草药：名称/类别/性味/功效/用量/禁忌/安全等级/易混淆品种/警示语/别名 |
| 导入 | 种子脚本（import_herbs.py / seed.py）批量入库 |
