# 开发启动指南

> 本文档固定「前后端启动与就绪验证」的标准做法，解决「终端输出看起来卡住」的误判问题。
> 适用于本机开发与演示环境（Windows PowerShell）。

## 一、标准启动命令

### 后端（FastAPI，端口 8001）

**必须后台启动**（命令立即返回，不阻塞终端），stdout/stderr 分别重定向到日志文件：

```powershell
Start-Process -FilePath "python" -ArgumentList "run.py" -WorkingDirectory "d:\CodeBuddy\herb-ai-agent\backend" -WindowStyle Hidden -RedirectStandardOutput "d:\CodeBuddy\herb-ai-agent\backend\server_stdout.log" -RedirectStandardError "d:\CodeBuddy\herb-ai-agent\backend\server_stderr.log"
```

**不要用前台 `python run.py` 阻塞启动**：后端是长驻进程、永不返回，前台方式会让命令面板一直挂起，看起来像「卡住」。启动后改用健康检查确认就绪（见下文）。

**必须使用系统 Python**（`python` / `py -3.12`），**禁用 `.venv\Scripts\python.exe`**：
- 本地自训练模型推理依赖 `torch/torchvision/pillow/numpy`，仅安装在系统 Python（`C:\Users\LENOVO\AppData\Local\Programs\Python\Python312`）；
- `.venv` 未装 torch，用它启动会报 `No module named 'torch'`，本地模型加载失败并全部回退百度；
- 本地模型加载成功的标志：首次识别日志出现「本地模型已加载（N 类，设备 cuda/cpu）」且识别结果 `channel=local`。

### 前端（Vue3 + Vite，端口 5173）

```powershell
cd d:\CodeBuddy\herb-ai-agent\frontend
npm run dev:raw
```

**必须用 `dev:raw`，不要用 `npm run dev`**：
- `npm run dev` 的 Vite 启动日志会被 npm 管道块缓冲（不足 4KB 不刷新），终端只显示 `> vite`，看起来像「卡住」，实际服务已就绪；
- `dev:raw` 直接用 `node` 运行 vite 二进制并关闭清屏（`--clearScreen false`），绕过缓冲层；
- `frontend/.npmrc` 已关闭 `audit/fund/update-notifier`，消除 npm 隐式联网检查的启动延迟隐患。

## 二、就绪验证（不看终端输出）

**长驻服务启动完成后终端没有新输出是正常现象**，不是卡死。判断就绪一律用健康检查：

```powershell
# 后端：应返回 HTTP 200
curl.exe -s -o NUL -w "HTTP %{http_code}" http://localhost:8001/api/health

# 前端：应返回 HTTP 200
curl.exe -s -o NUL -w "HTTP %{http_code}" http://localhost:5173
```

两者均返回 200，即前后端就绪，可直接访问 `http://localhost:5173`。

## 三、常见问题处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 前端终端停在 `> vite` 不动 | npm 管道缓冲（显示层假象） | 改用 `npm run dev:raw`；用 curl 验证就绪 |
| 后端终端没有输出 | 后台启动后无请求时无日志（正常） | 用 curl 健康检查验证 |
| 端口被占用 / 出现多个实例 | 旧实例未清理 | `netstat -ano \| findstr ":5173 :8001"` 查 PID → `taskkill /PID <pid> /F /T` 清理后重启 |
| 后端报 `No module named 'torch'` | 误用 `.venv` 启动 | 改用系统 Python 后台启动（Start-Process 方式） |

## 四、备注

- 本机 npm 配置了代理 `127.0.0.1:7897`，只影响联网操作（install/registry），不影响本地 dev server；
- 前后端重启后如仍异常，先看 `frontend/vite*.log`、`backend/server*.log` 与 `server*.err.log`。
