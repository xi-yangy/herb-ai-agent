# 多模态中草药图像识别智能体 - 演示脚本

> 本文档为两周实训结项答辩演示的**走位脚本**，包含环境准备、主线台词（对照真实页面）、备选 QA 应答与故障预案。所有话术与页面表现以当前实现为准；识别准确率等**以实际验证结果如实标注**，不虚标。
>
> - **版本**：v1.0
> - **创建时间**：2026-08-30
> - **依据文档**：PRD v1.2（`docs/prds/多模态中草药图像识别智能体-v1.0-prd.md`）、项目宪章 CODEBUDDY.md v1.4、部署说明 v1.0

---

## 1. 演示目标与时长

- **总时长**：主线演示 6–8 分钟 + 评委 QA 互动（备好 2–3 个追问话题，见第 4 节）；
- **一句话定位**：一款「拍照识别 + 用药安全提示 + 多模态问答」的中草药识别智能体；
- **三大演示亮点**：
  1. **识别 + 用药安全一体化**：识别即给安全等级三色提示，毒性药材强制全屏警示（不可跳过）；
  2. **分层信息卡**：同一结果白话科普 + 专业药典双视角；
  3. **多模态闭环**：结果页文本/语音追问，Qwen 真实回答 + 失败降级知识库。

---

## 2. 演示环境准备（前 30 分钟）

### 2.1 Checklist

- [ ] 后端已用**系统 Python** 启动（`python run.py`），日志出现「本地模型已加载（N 类，设备 cuda/cpu）」；
- [ ] 浏览器打开 http://127.0.0.1:5173 （前端 dev 服务已启动）或内网穿透公网地址；
- [ ] 演示浏览器为 **Chrome/Edge**（语音输入需要）；
- [ ] 已准备 3–5 张演示图片，建议覆盖：
  - 一张在库普通药材（如黄芪），用于主链路演示；
  - 一张**毒性药材**（如附子）图片，用于强制全屏警示演示（`safety_level=毒性` 才触发警示页）；
  - 一张**易混淆**品种（如金银花）图片，用于防雷警报卡辨析演示（金银花为普通药材，不触发警示页，仅展示易混淆辨析卡）；
  - 一张低置信/陌生图片（可选），用于「低置信度降级 + 引导重拍」演示；
- [ ] 网络通畅（Qwen 问答、百度兜底、语音输入均需联网）；
- [ ] 屏幕：桌面端 1280×800 投屏，结果页分栏可读（PRD U1）。

### 2.2 自检（可选快速跑一遍）

```text
/api/health → ok
识别一张在库图片 → channel=local
结果页追问一句 → Qwen 回答 + 免责声明
```

## 3. 主线走位与台词（对照真实页面）

> 说明：`【操作】` 为现场动作，`「台词」` 为可念的话术（可据自己语言调整，关键数字与合规表述不建议改动）。

### 第一幕：开场（约 30 秒）

- 【操作】停留在首页 `HomeView`，大屏可见品牌区「灵草 · 中草药识别」、三个技术亮点标签、安全三原则与拍摄小贴士。
- 「台词」：
  > 这是我们团队做的「多模态中草药图像识别智能体」。它的核心是：**拍照识别中草药 → 给出用药安全提示 → 还能用文字或语音追问**。与市面上纯识花的 App 不同，它把"识别"和"安全"绑定在一起——识别结果会直接给出普通 / 慎用 / 毒性三级安全提示，遇到高危易混淆品种还会强制弹全屏警示，防误采误食。

### 第二幕：识别主流程（约 1.5 分钟）

- 【操作】点击首页「拍照识别」（有相机则实拍演示，无相机环境点「相册上传」选演示图）→ 进入识别 loading → 跳转结果页 `ResultView`。
- 【操作】指向上方**安全等级色条**（普通 = 绿色 / 慎用 = 橙色 / 毒性 = 红色）与药材卡片（名称、置信度、识别通道）。
- 「台词」：
  > 上传照片后，后端按「自训练本地模型 → 百度植物识别 → 模拟数据」三通道调度，平均几秒出结果。左上角绿色标签代表这味药是普通药材，页面同时给出置信度和识别通道。
  > （可选强调）本项目**自训练了一个基于 ResNet50 的本地分类模型作为主通道**，针对我们整理的药材库做了迁移学习，减少对单一第三方 API 的依赖。

### 第三幕：分层信息卡（约 1 分钟）

- 【操作】滚动到 `LayeredInfoCard`，先展示默认展开的**白话科普卡**，再点击展开**专业药典卡**。
- 「台词」：
  > 同一个结果我们做了分层展示，照顾两类用户：**白话科普卡**面向普通消费者，用生活化语言讲"它有什么用、该怎么用、哪些人要注意"；**专业药典卡**面向中医药从业者，展示性味归经、功效主治、用法用量、禁忌与毒性原文。白话部分我们刻意用了"传统上/常用于"这类限定词，避免诊断性表述。

### 第四幕：高危强制警示（约 1.5 分钟）★ 演示亮点

- 【操作】回到首页，上传一张**毒性药材**图片（如附子，知识库 `safety_level=毒性`）。识别结果会自动跳转全屏警示页 `WarningGateView`。
- 【操作】刻意演示「无关闭入口」：页面只有「我已了解风险」一个按钮，无返回、无 X。
- 【操作】点击「我已了解风险」→ 进入结果页，顶部出现**鉴别防雷警报卡**（本药材 vs 易混淆高危品种辨析 + 警示语）。
- 【操作·可选】再上传一张**金银花**图片（普通药材），演示不弹警示页、但结果页展示「易与断肠草混淆」防雷警报卡的**易混淆辨析**场景，强调两类警示机制的差异。
- 「台词」：
  > 这是本项目最重要的安全设计：**高危判定宁严勿松**。识别到毒性药材时，强制全屏警示，没有关闭和跳过入口，用户必须确认已知晓风险才能进入结果。以附子为例，它含乌头碱类剧毒成分，生品严禁内服——我们在警示页直接给出毒性说明、禁忌提示和"切勿自行采摘服用"的特别提醒。结果页还有防雷警报卡，把附子与易混淆品种做对比辨析。这个警示逻辑上线前会经药师/教师复核（合规收口）。

### 第五幕：多模态问答 + 语音输入（约 2 分钟）★ 演示亮点

- 【操作】在结果页滚动到问答区 `QaPanel`，先点一个快捷标签（如「怎么用」「有什么禁忌」）发送文本问题 → 展示 Qwen 回答气泡 + 底部免责声明。
- 【操作】点击麦克风按钮 → 用语音问一句「这味药和什么容易混淆？」→ 语音转文字上屏 → 发送 → 展示回答。
- 【操作】（可选）若识别时带了图片，可演示**图文联合问答**（Qwen 看图 + 文字）。
- 「台词」：
  > 识别结果页支持多模态追问：可以打字，也可以直接语音提问。语音走浏览器原生的 Web Speech API，免费、无需额外 SDK。问题会结合当前识别结果上下文发给通义千问（Qwen），回答自动附带"仅供参考，不构成诊断或处方"的免责声明。
  > （降级演示，可选）如果 Qwen 不可用，系统不会报错中断，而是自动降级为**知识库结构化摘要**展示，并标注"已切换至本地知识库展示"，保证演示链路不断。

### 第六幕：历史 / 收藏 / 我的（约 30 秒，可选收尾）

- 【操作】返回首页 → 底部「历史」查看按时间分组的识别记录 → 「我的」查看收藏数、隐私授权管理。
- 「台词」：
  > 识别历史与收藏按降级方案存在本地，支持重新识别和删除；隐私授权在「我的」页可随时开关相机、相册、麦克风权限。

### 收尾（约 30 秒）

- 【操作】回到首页。
- 「台词」：
  > 以上就是我们的完整演示。一句话总结：**识别给结论、安全给警示、问答给延伸**——用多模态的方式，把"这是什么药"和"我怎么安全用"串成一条完整链路。谢谢各位，欢迎提问。

## 4. 备选 QA 应答要点

> 按项目**实测口径**回答，未验证项如实说明，不引用厂商自述作承诺。

| 可能的问题 | 应答要点 |
| --- | --- |
| 识别准确率多少？ | 本地自训练模型在验证集实测约 **77.8%**（如实标注）；为弥补单模型局限，采用「本地 → 百度 → 模拟」三通道：本地低置信自动回退百度植物识别，百度也不可用时兜底 mock，保证链路不断。未虚标为更高数字。 |
| 为什么要自训练模型？ | ① 摆脱对单一第三方 API 的依赖，识别自主可控；② 针对本项目整理的药材库做迁移学习（ResNet50 预训练权重微调），提升在库药材的针对性识别；③ 作为实训创新点，体现"数据采集 → 训练 → 部署 → 识别"完整闭环。 |
| 三通道怎么协同？ | 调度顺序：本地（`channel=local`）→ 置信度低于阈值（0.6）回退百度（`channel=baidu`）→ 凭证缺失/异常再兜 mock（`channel=mock`）。页面展示实际命中的通道。 |
| Qwen 不可用怎么办？ | 超时（默认 30s）或未配置凭证时**降级为知识库结构化展示**（功效/用法/禁忌摘要），回答带 fallback 标记并标注「已切换至本地知识库展示」，不阻塞结果页。视觉模型额度不足时自动回退纯文本问答。 |
| 语音输入的技术方案？ | Web Speech API（免费），需联网 + Chrome 系浏览器；演示环境用 Chrome。识别失败提示改用文本输入（PRD 边界策略）。 |
| 数据与隐私怎么保证？ | 用户上传图片仅用于本次识别，前端完成后即清除，服务端不持久化原始图片；首次使用弹窗说明相机/相册/麦克风权限用途，可拒绝并降级（拒绝相机则切相册）。 |
| 合规方面做了什么？ | 全流程固定免责声明（不构成诊断或处方）；毒性/禁用高危强制全屏警示、无跳过入口；知识库高风险字段（用法用量、毒性）上线前需人工/专家复核；白话文案统一用限定词避免诊断性表述。 |
| 之后怎么扩展？ | 预留了真伪鉴定、品相评估、药典比对、多图批量、结果分享、P2 远期项等扩展点；识别范围随百度 API 能力与本地知识库扩展。 |

## 5. 故障预案

> 演示前 15 分钟逐项确认主链路，以下预案按 PRD「边界情况与错误处理」表对齐。

| 故障场景 | 现场处理 | 话术 |
| --- | --- | --- |
| Qwen 超时 / 不可用 | 不做任何操作，等降级展示 | 「AI 问答当前不可用，我们自动切换到了本地知识库的结构化展示，不影响识别主流程——这也是我们的降级设计。」 |
| 识别显示 `channel=baidu` 而非 local | 不慌张，先看后端日志是否「本地模型已加载」；多半是启动时用了 `.venv` | 「当前是百度兜底通道。本地模型依赖的 torch 只装在系统 Python，需用系统 Python 启动后端才会走本地通道——这正好展示了我们的容错设计。」 |
| 语音按钮置灰 / 麦克风被拦 | 提示改用文本输入，点快捷标签继续演示 | 「语音输入需要联网和 Chrome 系浏览器的安全上下文，当前环境可能受限，我们切换文本输入，演示问答能力。」 |
| 断网 / 后端不可达 | 首页会显示后端离线提示；改用 mock 演示或先演示已打开的页面 | 「当前网络受限。系统对异常做了兜底，识别失败会回退演示数据，保证链路不中断。」 |
| 图片拍糊 / 低置信度 | 走「低置信度降级」页：相似品种列表 + 重新拍摄引导 | 「置信度低于阈值时我们不给直接结论，而是展示相似品种候选，并引导重新拍摄——避免误导用户。」 |
| 高危图片识别出意外结果 | 换一张已知的附子/高危图重演 | 警示触发条件为知识库安全等级=毒性，选择演示图时优先用已在库的高危品种。 |
