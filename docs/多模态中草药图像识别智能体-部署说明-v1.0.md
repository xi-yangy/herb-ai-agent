# 多模态中草药图像识别智能体 - 部署说明

> 本文档面向两周实训演示版（结项答辩），说明如何在**本机演示**、**内网穿透外网访问**两种场景下部署「多模态中草药图像识别智能体」，并给出上线前自检清单。
>
> 识别链路为「自训练本地模型（主通道）→ 百度植物识别（兜底）→ Mock（保底）」，多模态问答为「Qwen 真实调用（主）→ 知识库结构化展示（降级）」。**未验证能力如实标注，不虚标**。
>
> - **版本**：v1.0
> - **创建时间**：2026-08-30
> - **依据文档**：PRD v1.2（`docs/prds/多模态中草药图像识别智能体-v1.0-prd.md`）、项目宪章 CODEBUDDY.md v1.4

---

## 1. 部署方案总览

| 场景 | 方案 | 适用 |
| --- | --- | --- |
| 本地开发 / 联调 | 后端 FastAPI（:8001）+ 前端 Vite 开发服务器（:5173，代理 /api） | 日常开发、功能自测 |
| 演示（推荐） | 后端（:8001）+ 前端构建产物（静态服务）+ **内网穿透**对外 | 结项答辩，外网可访问 |
| 长期展示（备选） | 云服务器反向代理 + 前后端部署 | 实训结束后长期保留 |

> 演示统一走**方案二（本地 + 内网穿透）**：识别主链路（含自训练本地模型）与 Qwen 问答全部跑在本机，穿透只暴露访问入口，便于答辩现场演示与排障。

## 2. 前置环境

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Windows / macOS / Linux | — | 本项目在 Windows 11（PowerShell）下开发验证 |
| Python | **3.12** | 后端运行；3.14 暂不被 pydantic-core 支持 |

## 3. 本地部署（开发 / 自测）

### 3.1 后端

```powershell
cd d:\CodeBuddy\herb-ai-agent\backend

# ① 用系统 Python 安装全部依赖（含 torch，供本地模型推理）
#    requirements-dev.txt 含 -r requirements.txt，会连带安装 torch/torchvision 等
python -m pip install -r requirements-dev.txt

# ② 配置 .env（参考 .env.example，填写百度/Qwen 凭证、开启本地模型）
copy .env.example .env
```

> 提示：项目内的 `.venv` 未安装 torch，**不要**用 `.venv\Scripts\activate` + `pip install` 后启动运行，依赖请装在系统 Python 环境。

`.env` 关键字段（仅列用途，不写取值）：

| 分组 | 字段 | 用途 |
| --- | --- | --- |
| 数据库 | `DATABASE_URL` | SQLite 连接串（默认 `sqlite:///./herb_ai.db`） |
| CORS | `CORS_ORIGINS` | 允许跨域来源（开发期含 5173） |
| 百度识别 | `BAIDU_API_KEY` / `BAIDU_SECRET_KEY` | 百度智能云植物识别凭证 |
| 百度识别 | `BAIDU_ENABLED` | 置 true 启用；未配置凭证自动回退 Mock |
| 本地模型 | `LOCAL_ENABLED` / `LOCAL_MODEL_PATH` / `LOCAL_CLASSES_PATH` | 启用自训练模型主通道并指定产物路径 |
| 本地模型 | `LOCAL_CONFIDENCE_THRESHOLD` / `LOCAL_TOP_K` / `LOCAL_DEVICE` | 置信度阈值、相似列表条数、推理设备 |
| Qwen 问答 | `QWEN_API_KEY` / `QWEN_ENABLED` | 通义千问多模态问答凭证与开关 |
| Qwen 问答 | `QWEN_MODEL` / `QWEN_BASE_URL` / `QWEN_TIMEOUT` | 模型名、OpenAI 兼容接口地址、超时（秒） |

**启动（重要）**：

```powershell
# ③ 必须用系统 Python 启动（python / py -3.12），绝不可用 .venv\Scripts\python.exe！
python run.py
```

> ⚠️ **本地模型环境约定**：自训练模型推理依赖 `torch/torchvision/pillow/numpy`，这些**只安装在系统 Python**（如 `C:\Users\LENOVO\AppData\Local\Programs\Python\Python312`）；项目内 `.venv` **未安装 torch**。用 `.venv\Scripts\python.exe` 启动会报 `No module named 'torch'`，本地模型加载失败并自动回退百度（识别结果 `channel=baidu`）。
>
> ✅ **本地模型加载成功的判定标志**：后端日志出现 `本地模型已加载（N 类，设备 cuda/cpu）`，且识别结果 `channel=local`。

启动后验证：

- 接口文档：http://127.0.0.1:8001/docs
- 健康检查：http://127.0.0.1:8001/api/health

### 3.2 前端（开发模式）

```powershell
cd d:\CodeBuddy\herb-ai-agent\frontend
npm install
npm run dev        # http://127.0.0.1:5173
```

Vite 开发服务器已将 `/api` 代理到 `http://127.0.0.1:8001`（见 `vite.config.js`），**需先启动后端再启动前端**。

## 4. 演示部署（本地 + 内网穿透，推荐）

### 4.1 后端

与 3.1 相同：**系统 Python** 启动 `python run.py`，监听 `0.0.0.0:8001`。

### 4.2 前端构建产物

> 生产构建下 **Vite 的 `/api` 代理不生效**，需要把前端对后端的请求指向真实地址。本项目前端 `src/api/http.js` 使用相对路径 `/api`，因此对外访问时必须让**静态页面与后端接口同源**，或加一层反向代理转发 `/api`。

推荐做法（同源反代）：内网穿透同时暴露**前端静态服务**，再用一个小型反向代理把 `/api` 转发到 `127.0.0.1:8001`。

```powershell
cd d:\CodeBuddy\herb-ai-agent\frontend
npm run build          # 产物 dist/
npm run preview -- --host 0.0.0.0 --port 8080   # 托管 dist/（含静态服务）
```

> 说明：`vite preview` 只做静态托管，**不会转发 /api**。若希望 8080 端口同时代理后端接口，可改用 `serve` + 反向代理（如 nginx），或使用下方 5.1 中「同时穿透两个端口」的简化链路。

**两种穿透链路（任选其一）**：

| 链路 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 穿透后端端口 | 直接把 `http://127.0.0.1:8001` 暴露公网，外网地址就是后端；但前端页面仍在本机 5173 打开 | 最简单 | 外网只能访问接口，页面不完整；页面必须在本机浏览器打开 |
| B. 穿透前端静态服务（推荐） | 前端 `npm run preview` 托管 dist/ + 反向代理 `/api` → 8001，整体暴露公网 | 外网可访问完整页面 | 需处理 `/api` 转发 |

> 演示场景建议：**页面走本机浏览器（5173），把「后端 :8001」用内网穿透暴露给手机等外部设备**演示识别接口即可；若需完整页面外访，则走链路 B（配 nginx 或 Caddy 把 `/api` 反代到 8001）。

### 4.3 稳定性演练要求

- 演示前连通本地链路并保持 **≥30 分钟**不中断（PRD U2 要求）；
- 演练内容：连续识别（本地/百度/模拟三通道各冒烟）、结果页追问（Qwen 或降级）、语音输入、高危警示页触发。

## 5. 内网穿透方案

> 目标：让外部设备（如手机 / 评委电脑）通过公网地址访问本机服务。以下两种免费方案任选，按实际可用的为准。

### 5.1 ngrok（免费版）

```powershell
# ① 安装并注册（官网下载，登录后复制 authtoken）
ngrok config add-authtoken <YOUR_AUTHTOKEN>

# ② 暴露后端（先确保后端已用系统 Python 启动）
ngrok http 8001
```

输出中的 `https://xxxx.ngrok-free.app` 即为公网地址。验证：

```powershell
curl https://xxxx.ngrok-free.app/api/health
```

若走链路 B（完整页面），则：

```powershell
ngrok http 8080     # 前端静态服务端口；另配 nginx/Caddy 把 /api 转发到 8001
```

### 5.2 cpolar（国内免费版，网络可达性更好）

```powershell
# ① 安装并注册（官网下载 Windows 版，登录后复制 authtoken）
cpolar authtoken <YOUR_AUTHTOKEN>

# ② 暴露后端
cpolar http 8001
```

输出中的 `https://xxx.r3.cpolar.cn`（或 `http://xxx.cpolar.top`）即为公网地址。

> **关于 HTTPS 与安全上下文**：Web Speech API 要求安全上下文（`https://` 或 `http://localhost`）。ngrok / cpolar 免费版默认提供 `https` 地址，满足语音输入条件；若浏览器仍拦截麦克风，请在地址栏左侧站点设置中允许麦克风权限。语音在演示中失败时，按 PRD 边界策略**提示改用文本输入**，不阻塞主流程。

### 5.3 常见问题

| 现象 | 排查 |
| --- | --- |
| 外网打开 /api/health 不通 | 后端是否已启动；穿透端口是否与后端一致（8001） |
| 外网页面能开但识别失败 | 是否走了链路 B 且 `/api` 转发已配置；浏览器控制台查看 404/502 |
| 识别结果显示 `channel=baidu` | 本地模型未加载（多半用了 `.venv` 启动，或模型路径错误），按 3.1 节改用系统 Python 并核对日志 |
| 语音按钮置灰 / 麦克风被拦截 | 需 Chrome 系 + 联网 + https/localhost；站点设置允许麦克风；仍失败则提示改用文本输入 |

## 6. 云服务器备选方案（长期展示）

> 备选不展开：实训结束后如需长期可访问，可迁移方案二（云服务器）。要点如下：

1. 云服务器（含公网 IP，如 2C2G 以上即可）安装 Python 3.12、Node ≥ 20；
2. 后端：复制 `backend/` 与 `data/`，系统 Python 安装依赖，`python run.py` 后台常驻（建议用 systemd/nssm 托管）；
3. 前端：`npm run build` 产物交由 nginx/Caddy 托管，并把 `/api` 反向代理到本机 8001；
4. 安全：`CORS_ORIGINS` 改为实际域名；HTTPS 证书（Let's Encrypt）保证语音输入可用。

## 7. 上线前 Checklist（演示前一天执行）

- [ ] **健康检查**：`http://127.0.0.1:8001/api/health` 返回 ok
- [ ] **三通道冒烟**：
  - `channel=local`：本地模型已加载（日志出现「本地模型已加载」），识别一张在库药材图片返回 local；
  - `channel=baidu`：临时关闭本地模型（或低置信图片）验证百度兜底链路；
  - `channel=mock`：断网 / 凭证缺失时验证 mock 保底不报错；
- [ ] **多模态问答**：结果页追问返回真实 Qwen 回答（含免责声明）；关闭 Qwen 后返回知识库结构化展示并标注「已切换至本地知识库展示」
- [ ] **语音输入**：Chrome 下语音转文字可用；失败时提示改用文本输入
- [ ] **高危警示**：毒性药材（如附子）识别触发强制全屏警示确认页，无跳过入口；易混淆品种（如金银花）在结果页展示「易与断肠草混淆」防雷警报卡
- [ ] **免责声明**：首页、结果页、问答回答、警示页均含「仅供参考，不构成诊断或处方」类表述
- [ ] **内网穿透**：外网地址可访问、稳定保持 ≥30 分钟
- [ ] **性能**：识别接口从上传到结果 ≤3s（P95）；图片上传前压缩 ≤1MB
