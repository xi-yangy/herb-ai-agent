> 各位老师好，我的项目是《多模态中草药图像识别智能体》。一句话概括：用户拍照或上传一张中草药图片，系统识别出是什么药，同时给出用药安全提示，还能用文字或语音追问。这个项目由我个人主导、与 AI 协作完成。接下来我从设计思路、技术算法到创新难点，完整介绍一下。

## P2 设计思路

- 痛点：大众对不认识的草药易**误采误食**；网络信息鱼龙混杂；市面识花 App 只认鲜植物、**不含用药安全提示**；
- 定位：把「识别」和「安全」绑定，识别即给安全分级（普通 / 慎用 / 毒性）；
- 双画像：大众消费者（要"怎么安全用"）+ 中医药从业者（要专业药典信息）；
- 差异化：不做识花 App，做**有安全底线的中药识别**。

**讲解词**：
> 设计思路从痛点出发：大众遇到不认识的草药容易误采误食，网上的信息又难辨真伪，而市面识花 App 只能认植物，回答不了"有毒没毒、怎么用"。所以我把"识别"和"安全"绑定，识别结果直接给安全等级和警示；同时服务两类人——普通大众看白话科普，从业者看专业药典信息。

## P4 技术架构

- 前端：Vue 3 + Vant + Tailwind（H5 响应式，移动优先 / 桌面 ≥1024px 分栏）；
- 后端：Python FastAPI（识别代理、知识库、问答、历史）；
- 识别引擎：**自训练本地模型（主）→ 百度植物识别（兜底）→ Mock（保底）**；
- 多模态：**通义千问 Qwen（主）→ 知识库结构化（降级）**；
- 数据：SQLite，172 味药材知识库（功效 / 禁忌 / 毒性 / 安全等级）。

**讲解词**：
> 技术上是前后端分离：前端 Vue3 + Vant，移动优先也适配桌面大屏；后端 FastAPI。识别引擎是三通道设计——自训练本地模型是主通道，低置信度自动回退百度，再不可用就用模拟数据保底，链路永远不断。多模态问答用通义千问，失败降级本地知识库。数据层是 SQLite，内置 172 味药材的结构化知识库。

---

## P5 核心算法

- **自训练分类模型**：自建数据集 → ResNet50 迁移学习 → 识别主通道，覆盖 **93 类**常用药材，验证集实测准确率约 **77.8%**（如实标注）；
- **三通道调度**：local 置信度 < 0.6 → 回退 baidu → 异常兜底 mock，页面标注实际通道；
- **低置信策略**：不给直接结论，展示相似品种列表 + 引导重拍，避免误导；
- **问答降级**：Qwen 超时 / 未配置 → 知识库结构化摘要 + fallback 标记。

**讲解词**：
> 核心算法是自训练的 ResNet50 分类模型：整理数据集、迁移学习、部署成主通道，覆盖 93 类常用药材，验证集实测准确率约 77.8%，如实标注。调度上，本地置信度低于 0.6 自动回退百度，异常再兜底 mock；低置信时不给直接结论，而是展示相似品种引导重拍，避免误导。问答侧 Qwen 不可用就降级为知识库结构化展示，链路不中断。

## P6 功能清单

- **识别**：拍照 / 相册上传，≤3s 出结果，图片压缩 ≤1MB；
- **安全**：三级安全色标、毒性强制全屏警示（不可跳过）、易混淆防雷警报卡；
- **信息**：白话科普 + 专业药典**分层信息卡**；
- **多模态**：结果页文本 / 语音追问（Web Speech API）、回答附免责声明；
- **历史 / 收藏 / 我的**：本地化记录、权限管理；
- **首次授权**：隐私说明弹窗，可拒绝并降级。

**讲解词**：
> 功能上聚焦一条主线：识别、安全、信息、多模态。识别支持拍照和相册上传，几秒出结果；安全上有三级色标和毒性强制警示；信息是白话加药典的分层卡；多模态支持语音追问；另有历史收藏和首次授权说明等配套功能。

## P7 界面设计（配图：结果页 + 警示页 各 1 张）

- 移动优先 H5，桌面 ≥1024px **分栏布局**（左图对比 / 右信息卡 + 警示区），投屏可读；

- 全屏警示页**无关闭 / 跳过入口**，只有"我已了解风险"；
- 分层信息卡：白话科普（限定词表述）+ 专业药典双视角；
- 品牌视觉：「灵草」绿色系，统一组件（Vant + Tailwind）。

**讲解词**：
> 界面设计围绕安全和可读性：结果页一屏呈现安全色标和识别信息，桌面端分栏展示；毒性药材触发全屏警示，没有关闭和跳过入口，视觉上强制（指截图）。信息卡分白话和专业两档，照顾两类用户；整体统一绿色系品牌视觉。**设计上就是这样，下面我现场跑一遍真实链路。**

## ★ 实机演示衔接（P7 后切入，约 2 分钟）

**【操作】切换到浏览器（已提前打开结果页/可快速操作的页面）**
- ① 相册上传一张在库普通药材图（如黄芪）→ 识别 loading → 结果页，快速指向安全色标 + 置信度 + 通道；
- ② 返回上传一张**毒性药材**图（如附子）→ 全屏警示页，强调「只有『我已了解风险』一个按钮，无跳过入口」→ 点击进入，指向防雷警报卡；
- ③ 回到结果页，点快捷标签问一句 → 展示回答 + 免责声明；再点**麦克风**语音问一句 → 语音转文字上屏 → 出回答。

**【台词（衔接）】**
> 这是刚才讲到的识别与安全链路：普通药材几秒出结果，绿色标签、置信度、识别通道一屏可见；毒性药材强制全屏警示，不可跳过；结果页还能文本或语音追问，回答自动附"仅供参考，不构成诊断或处方"的免责声明。

**【故障预案】**
| 故障 | 处理 |
| --- | --- |
| Qwen 不可用 | 不操作，等降级展示：「AI 不可用自动切换本地知识库，不阻塞主流程——这是降级设计。」 |
| 语音被拦 / 置灰 | 改用文本输入，点快捷标签继续演示。 |
| 识别 channel=baidu | 「当前是百度兜底通道，展示容错设计。」 |
| 图片拍糊 / 低置信 | 走相似品种列表 + 引导重拍，避免误导。 |

## P8 创新点

1. **自训练本地模型作主通道**：走通"数据采集 → 训练 → 部署 → 识别"完整工程闭环，摆脱对单一第三方 API 的依赖；
2. **安全合规闭环**：高危强制警示不可跳过 + 全流程免责声明 + 防雷警报卡，把"安全"从口号做成硬机制；
3. **多模态交互**：图文 + 语音问答，Qwen 真实调用 + 降级兜底，演示链路不断。

**讲解词**：
> 创新点有三个。一是自训练本地模型做主通道，整个数据到识别的闭环自己做通，减少第三方依赖；二是安全合规闭环，高危警示不可跳过、免责声明全覆盖，这是同主题项目里少见的硬机制；三是多模态交互，文本加语音都能问，且带容错降级。

## P9 难点与解决

| 难点 | 分析与解决 |
| --- | --- |
| 单模型准确率有限（实测 77.8%） | 承认局限，低置信回退百度 + 相似列表引导，不误导用户 |
| 第三方 API 依赖 / 可用性不确定 | 本地模型主通道 + Qwen 降级知识库，链路永远不断 |
| 语音 / 识别环境受限 | Web Speech API 需 Chrome + 联网，失败提示降级文本输入 |
| 数据合规 | 图片不持久化、权限说明、高风险字段人工复核、不虚标 |

**讲解词**：
> 项目最大的难点是识别准确率和外部依赖的不确定性。我如实标注准确率 77.8%，用三通道容错和低置信引导弥补；对 Qwen、语音这些外部能力做了边界分析——边界内使用、边界外降级，不阻塞主流程。这些难点也是我和 AI 协作中反复验证、不断修正的对象。

**左栏｜批判性思维（10 分）**
- **发现并纠正 AI 错误**（真实案例）：
  - **误删事故 → 机制改进**：AI 编写的清理脚本因目录匹配逻辑缺陷（"仅删除乱码目录"误写成"文件名不含「多」「模」两字的所有中文目录"），误删了 4 个无关目录。我复盘定位根因、修正逻辑，并从此确立硬性红线——**所有删除/破坏性操作必须先列清单、经人工确认后才执行**；
    - **PPT 展示文字（对话记录原文摘录）**：「AI 的目录匹配逻辑写成了『文件名不含"多""模"两字的所有中文目录』，误删了 4 个无关项目目录。AI 立即停止操作、承认错误、定位根因——责任在我。我（人）复盘后确立红线：删除/破坏性操作必须先列清单、经人工确认后才执行。」（旁附对话记录截图佐证）
  - 实测发现「用 .venv 启动 → torch 缺失 → 识别静默回退百度」，纠正环境方案；
  - 解决 git 中文提交乱码（GBK），改 UTF-8 提交文件方式。
- **多角度验证**：准确率不用厂商自述，自建验证集实测 77.8%；三通道逐一冒烟；高危警示有单元测试。
- **能力边界分析**：77.8% 局限 → 回退兜底；Qwen / 语音边界外降级；百度覆盖物种不虚标；中文路径引发 AI 编码乱码 → 主动改英文项目名（herb-ai-agent）。

## P11 总结与展望

- **总结**：聚焦"识别 + 安全 + 多模态问答"核心闭环，做深做稳；三通道容错保证链路稳定；合规红线全程落地；

**讲解词**：
> 总结下来，我有意把功能收敛在识别、安全、问答这条主线上，把核心链路做深做稳，而不是铺开一堆浅尝辄止的功能。展望上，模型可以靠补数据重训持续扩类，架构上预留了真伪鉴定、药典比对、多图批量等扩展点，是一个可长期演进的基础。
