## 1. 项目概述

**一句话定位**：一款面向大众消费者与中医药从业者的「多模态中草药图像识别智能体」，通过拍照/上传图片（可叠加文本、语音等模态输入）快速识别中草药，并提供功效、禁忌、安全提示与药典级专业信息。

**核心价值主张**：

- **识别**：识别鲜植物与常见中草药，快速给出识别结果；
- **安全**：面向大众突出用药安全警示与免责声明，降低误食/误用风险；
- **专业**：面向从业者提供真伪、品相鉴定与药典信息比对能力；
- **多模态**：图文 + 语音交互，降低使用门槛。

## 2. 用户画像

依据已确认的双核心场景，拆分两类用户画像。**画像一（从业者）为专业价值承载者，画像二（消费者）为规模与合规重点**。

### 2.1 画像一：中医药专业 / 从业者

| 维度 | 描述 |
| --- | --- |
| 基本信息 | 25–55 岁；中医师、执业药师、中药材采购/验收/质检人员、中医药院校师生 |
| 使用场景 | 药材入库验收、采购比价、临床用药参考、教学与科研；对象多为**常见中草药** |
| 核心诉求 | ① 药材**真伪鉴定**（正品 / 伪品 / 掺假）；② **品相评估**（产地、年份、等级规格）；③ 与《中国药典》等权威信息**比对**（基原、性味归经、功效主治） |
| 主要痛点 | 人工鉴定依赖个人经验、专家资源稀缺；纸质药典/文献检索繁琐；市面识花类 App 只认鲜植物、识别范围有限；识别结果缺乏权威依据、不敢采信 |
| 使用频率 | 中高频（验收/门诊/教学日常触发） |
| 技术熟练度 | 中高，可接受专业工具与较复杂交互 |
| 设备偏好 | 手机为主、PC 为辅 |

### 2.2 画像二：消费者（大众用户）

| 维度 | 描述 |
| --- | --- |
| 基本信息 | 18–60 岁；养生爱好者、户外徒步/摄影人群、家庭照护者（关注家人用药）、普通患者家属 |
| 使用场景 | 野外/市场/家中随手拍下不认识的中草药；购买或服用前查询**功效、用法与禁忌**；自采草药想确认是否可食/可用 |
| 核心诉求 | ① 快速知道"这是什么药"；② 查清**功效、用法用量、禁忌、副作用**；③ 明确的**安全警示**（尤其易与有毒植物混淆时） |
| 主要痛点 | 不认识易误采误食；网络信息鱼龙混杂难辨真伪；看不懂专业术语；无法区分相似植物（如"金银花 vs 断肠草"类高危场景） |
| 使用频率 | 低频偶发，随场景触发 |
| 技术熟练度 | 中低，追求"打开即用、拍完即懂" |
| 设备偏好 | 智能手机（拍照为主） |

### 2.3 两类画像关键差异与产品含义

| 维度 | 从业者（画像一） | 消费者（画像二） | 产品含义 |
| --- | --- | --- | --- |
| 识别对象 | 常见中草药 | 鲜活植物/常见药材 | 识别引擎基于**百度植物识别 API** + 本地知识库匹配 |
| 信息深度 | 药典级、可溯源 | 白话科普 + 安全提示 | 同一结果**分层展示**（简版 / 专业版） |
| 核心诉求 | 真伪、品相、依据 | 是什么、能不能用、危险吗 | 功能矩阵中两者需求均有对应条目 |
| 合规红线 | 准确性责任 | **非诊断、非处方、就医提醒** | 全流程医疗免责声明为强制项 |

> **合规要点（全产品适用）**：任何识别/查询结果不得构成诊断或处方建议；必须显著提示"仅供参考，如有不适请咨询执业医师/药师"；对毒性药材、易混淆高危品种进行**分级强警示**。

## 3. 竞品分析

### 3.1 竞品选取说明

| 竞品 | 选取理由 |
| --- | --- |
| **形色**（主竞品） | 国内识别类头部 App，产品形态（拍照识别 + 信息展示 + 社区）与本项目最相似，已通过官网实地调研 |
| 花伴侣专业版（植物智） | 中科院植物研究所出品，权威性标杆，可对标专业数据能力 |
| 百度植物识别 API | 国内主流 AI 识别开放能力，可作为技术底座或合作/替代方案 |

### 3.2 主竞品「形色」分析

> 信息来源：形色官网（xingse.net / xingseapp.com）实地访问，调研日期 2026-08-27。官网标注数据仅供参考，部分需结合应用商店实际验证。

**① 功能**

- 拍照识别植物：官方宣称支持 **4 千余种**常见植物，**准确率超过 98%**，约 1 秒出结果，并附"花名 + 比对图"；
- 内容增值：花语、诗词、植物趣闻、花语壁纸、精选文章；
- 社区生态：话题社区、全球植物景点攻略（宣称用户遍布 209 个国家和地区、每日上传 200 万张图片）；
- 人工兜底：鉴定区入驻"识花大师"，支持达人鉴定、专家互动、鉴定榜单；
- 商业化：开放 API 能力对外输出识别服务。

**② 页面风格**

- 清新自然的绿色治愈系，图文卡片式排版，走"赏花识花生活方式"路线；
- 视觉以植物实拍大图 + 柔和配色为主，品牌感强、氛围轻松，面向大众娱乐与兴趣人群。

**③ 易用性**

- 核心流程极短：打开 → 拍照 → 出结果，学习成本低；
- 面向"休闲识花"场景设计，流程轻量、无强制注册障碍（需实际下载验证）；
- **短板**：不涉及药用价值、功效禁忌与安全提示；结果缺乏权威出处，娱乐属性大于专业属性。

### 3.3 参考竞品速览

**花伴侣专业版（植物智，iPlant）**

- 中科院植物研究所主持开发，能识别 **2 万种**野生及栽培植物，覆盖中国 **96%** 常见植物；
- 定位专业服务：植物分类学、资源调查、物种保护；权威背书强；
- 偏科研/专业场景，大众易用性与内容趣味性弱于形色，同样不覆盖药用安全与用药指导。

**百度植物识别 API**

- 可识别 **2 万+** 常见植物、近 **8 千**花卉，返回名称、置信度及百科信息，支持 EasyDL 定制训练；
- 计费约 29 元/万次（次数包，官方页面标注，供成本估算参考）；
- 以 API 能力形式存在，无完整 C 端产品形态，可作本项目识别引擎的技术选型选项之一。

### 3.4 差异化机会（本项目的立足点）

| 对比维度 | 形色 / 花伴侣 | 本项目机会点 |
| --- | --- | --- |
| 识别对象 | 鲜活的观赏植物为主 | 覆盖常见中草药，直击从业者与消费者真实用药场景 |
| 药用价值 | 无 | **功效、用法用量、禁忌、毒性警示**为核心功能 |
| 用药安全 | 无 | **分级安全警示 + 医疗免责声明**，合规且建立信任 |
| 信息权威性 | 娱乐百科 | 对接《中国药典》等权威数据，标注来源与置信度 |
| 交互形态 | 纯图片识别 | **多模态**：图文 + 语音问答，降低查询门槛 |
| 人群覆盖 | 泛兴趣用户 | 从业者（专业鉴定）+ 消费者（安全识别）双画像分层服务 |

## 4. 功能矩阵

### 4.1 优先级定义

| 级别 | 定义 | 对应策略 |
| --- | --- | --- |
| **P0** | MVP 必备：核心识别闭环 + 安全合规底线，缺一不可 | 首发版本必须交付 |
| **P1** | 重要增强：显著提升体验或专业价值 | 首发后第一迭代 |
| **P2** | 远期规划：生态扩展 / 商业化 / 智能化延伸 | 视数据与资源择机启动 |

> **两周演示版口径（2026-08-28 更新）**：本项目实际为 2 周暑期实训、不做真实上线，交付目标为结项演示。因此上表 P0/P1/P2 仅作**远期迭代参考**，两周内的实际取舍按「必做 / 降级 / 砍掉」三档重新划分（详见 4.3 里程碑建议）：
> - **必做（核心闭环 + 创新点 + 多模态）**：识别主流程、安全合规、基本信息查询、**多模态图文+语音问答（P1 提升为必做，支撑项目名）**、语音输入、隐私授权；
> - **降级（简化实现）**：识别历史与收藏、注册登录（本地存储）、拍摄部位引导；
> - **砍掉（口头提及/远期）**：真伪鉴定、品相评估、药典比对、单味药材百科、多图/批量识别、离线识别、结果分享及全部 P2 项。

### 4.3 里程碑建议

**两周演示版排期（本次实训实际执行）**：

- **第 1 周**：打通「图片 → 识别 → 结果」核心闭环 + 安全警示 + 分层信息卡，并完成多模态问答后端（Qwen 调用）；验证百度与 Qwen API 额度；
- **第 2 周**：结果页追问交互 + 语音输入（Web Speech API）+ 桌面投屏适配 + 本地/内网穿透部署演练 + 演示脚本。

**远期参考（两周内不做，仅供后续迭代）**：

- **MVP（P0）**：以"拍照识别 + 安全警示 + 基本信息查询 + 历史记录"形成最小可用闭环，突出与竞品的差异化（用药安全与专业信息）；
- **迭代一（P1）**：上线专业鉴定能力（真伪/品相/药典比对），服务从业者人群，建立权威数据与专家背书；
- **远期（P2）**：依据数据与资源情况，逐步开放社区、专家鉴定与行情等扩展能力。

> 注：多模态问答已从原 P1 提前至两周必做（项目名支撑），故「迭代一」中仅保留专业鉴定相关能力。

## 5. UI/页面结构

> 产品形态为 **Web/H5，移动优先 + 桌面端大屏适配（响应式）**：手机浏览器以单栏移动布局使用；电脑浏览器（结项答辩/投屏演示）自动切换为桌面分栏布局。页面视觉方向为「清新自然、专业可信、移动优先、卡片化、高辨识度警示」。

### 5.1 信息架构（IA）

导航四模块 + 两级详情页，随断点切换形态：

```
应用
├─ 导航
│  ├─ 移动端：底部导航四 Tab（首页 / 百科 / 历史 / 我的）
│  ├─ 桌面端：顶部导航栏 + 侧边栏（同一模块，布局适配）
│  ├─ 首页（识别入口）   ← 主 CTA：拍照识别 / 相册上传
│  ├─ 百科              ← 药材百科浏览/搜索
│  ├─ 历史              ← 识别记录（时间线）
│  └─ 我的              ← 账户、收藏、隐私、免责声明
├─ 二级页面
│  ├─ 识别结果页        ← 识别主流程落点，含安全警示区
│  ├─ 药材百科详情页    ← 功效/用法/禁忌/毒性/图片库
│  └─ 高危警示页        ← 强制全屏确认页（不可跳过）
└─ 弹层/组件
   ├─ 拍摄部位引导（首次识别）
   ├─ 隐私授权说明（首次）
   └─ 多模态问答输入（文本 + 语音）
```

### 5.2 核心页面清单

| 页面 | 主要元素 | 说明 |
| --- | --- | --- |
| **首页（识别入口）** | 大按钮式 CTA（拍照 / 上传）、近期识别快捷入口、新手指引 | 打开即用，突出核心动作 |
| **识别结果页** | 药材名称 + 置信度 + 相似品种对比图；分层信息卡（白话科普卡 / 专业药典卡）；安全警示区；追问入口 | 双画像分层服务在此落地；高危品种触发强警示 |
| **药材百科详情页** | 功效主治、用法用量、禁忌、毒性、基原/炮制、图片库；收藏/分享 | 内容资产承载页 |
| **历史记录页** | 按时间分组、可收藏/重新识别/删除 | 支撑留存与追溯 |
| **个人中心** | 账户信息、我的收藏、隐私设置、免责声明 | 合规入口集中 |

**桌面端（大屏/投屏）适配要点**

- **识别结果页分栏布局**：左栏为识别图片 + 相似品种对比；右栏为信息卡（简版/专业版）与安全警示区，一眼看清完整结论，适合投影演示；
- **首页 CTA 放大化**：桌面端拖拽/点击上传区域更大，识别按钮尺寸适配鼠标操作；
- **投影可读性**：正文与警示文案字号在桌面断点适当放大，警示区保持高对比度配色，确保远端投影清晰；
- **导航形态**：底部 Tab 转为顶部/侧边导航，页面内容宽度自适应，最大阅读宽度约 1200px。

### 5.3 关键操作流程

**流程一：识别主流程**

```
打开首页 → 选择拍照/上传 → 拍摄部位引导（首次）→ 识别中（≤3s）→ 结果页
        → 正常结果：分层信息卡展示
        → 高危/易混淆：强制全屏警示确认页（不可跳过）→ 确认后进入结果页
```

**流程二：多模态问答流程**

```
结果页/百科页 → 点击"追问" → 输入问题（文本或语音转文字）
        → LLM 结合识别结果生成回答 → 附带免责声明 → 支持追问历史
```

**流程三：首次使用合规流程**

```
首次打开 → 隐私授权说明（相机/相册/麦克风 + 数据用途）→ 同意后进入首页
```

### 5.4 安全设计要点

- 高危/易混淆品种（如金银花 vs 断肠草、乌头类）识别结果**强制全屏警示确认**，无跳过入口；
- 所有结果页底部固定显示免责声明条："结果仅供参考，不构成诊断或处方，如有不适请咨询执业医师/药师"；
- 警示采用高辨识度配色（红/橙）与图标，与常规结果形成强视觉区分。

## 6. 技术方案

> 本节为**需求文档粒度**的选型建议与架构概要，供评审与实训展示参考；具体实现可在开发阶段细化，不写实现代码。

### 6.1 产品形态与技术栈

| 层 | 技术选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + Vant + Tailwind CSS | H5 响应式：移动优先，桌面端大屏适配 |
| 响应式断点 | 移动端 ≤375px / 平板 768px / 桌面 ≥1024px | 移动端单栏、桌面端分栏展示 |
| 前端增强 | PWA | 可安装、离线缓存（配合离线识别 P1 项） |
| 多模态交互 | 通义千问（Qwen）API | 图文/语音问答、结果解读 |
| 语音输入 | Web Speech API（免费）或讯飞开放平台 | 语音转文本，降低输入门槛 |
| 后端 | Python FastAPI | 识别代理、知识库查询、历史记录接口 |
| 数据存储 | SQLite（起步）/ MySQL | 药材知识库、用户历史 |
| 部署 | 两种方案：本地 + 内网穿透 / 云服务器（见 6.4） | 视演示环境与资源选择 |

### 6.2 识别引擎选型对比

| 方案 | 成本 | 周期 | 难度 | 识别效果 | 展示价值 |
| --- | --- | --- | --- | --- | --- |
| **百度植物识别 API（已确定采用）** | 低（有免费额度） | 短 | 低 | 覆盖常见植物与中草药，返回名称/置信度 | 中（调用成熟能力，配合本地知识库增值） |

**确定采用：百度植物识别 API**

- 调用百度植物识别 API 识别图片，取 top-k 候选匹配本地知识库；
- 低置信度时降级为"相似品种列表"并引导重拍，避免直接给不靠谱结论；
- 识别失败/未配置凭证时回退 Mock 演示数据，保证演示链路不中断。

### 6.3 关键组件与数据流

```
[前端 H5] 拍照/上传 → 图片压缩预处理 → 识别请求
      → [后端] 调用百度植物识别 API（未配置/失败时回退 Mock）
      → 置信度阈值判定 → 知识库匹配（药材信息/安全等级/相似品种）
      → 结果组装（简版/专业版分层）→ 安全警示判定（高危触发强警示）
      → 返回前端展示 → 历史记录入库
[多模态问答] 识别结果 + 用户问题（文本/语音）→ LLM 生成回答 → 附免责声明返回
```

**关键设计点**

- **置信度阈值**：低于阈值时引导"换个角度/部位重拍"，并降级为"相似品种列表"而非直接给出结论；
- **安全等级字段**：知识库每条药材含安全等级（普通/慎用/毒性），识别结果联动 UI 警示策略；
- **性能**：识别接口目标 ≤ 3s（含网络），图片前端压缩后上传（≤ 1MB）；
- **可观测性**：识别请求日志、失败率统计、LLM 调用量统计，支撑调优。

### 6.4 部署方案（两种备选）

| 方案 | 方式 | 优点 | 局限 | 适用场景 |
| --- | --- | --- | --- | --- |
| **方案一：本地 + 内网穿透** | 开发机运行服务，内网穿透（如 cpolar / ngrok / frp）暴露公网地址 | 零服务器成本、调试方便 | 依赖本机持续运行、带宽与稳定性受限 | 日常开发与结项演示 |
| **方案二：云服务器** | 部署到云主机（学生优惠/免费额度），公网直接访问 | 稳定可长期访问、演示不受本机影响 | 有维护成本、需备案/安全配置 | 成果长期展示、多人同时访问 |

**建议**：开发与演示以**方案一**为主，成本低、上手快；若需在结项后持续对外展示，可迁移到**方案二**。两种方案前端均无需改动，仅更换后端地址。

## 7. 数据来源与合规

### 7.1 药材知识库来源

| 数据项 | 建议来源 | 备注 |
| --- | --- | --- |
| 药材基原、性味归经、功效主治 | 《中国药典》公开条款、权威公开资料 | 仅引用公开可查信息，**注明出处**；不整本复制版权内容 |
| 用法用量、禁忌、毒性 | 权威科普/教材公开内容 + 药师复核 | 高风险字段需人工/专家复核后再上线 |
| 相似品种辨析 | 公开鉴别文献、图谱资料整理 | 用于高危易混淆提示 |
| 药材图像 | 公开图像数据集（如 iPlant 植物图像库等公开资源）、团队自采 | 标注来源与许可协议 |

### 7.2 版权合规要点

- 《中国药典》等内容受版权保护，项目仅做**引用与摘要**并标注来源，不整本复制、不用于商业分发；
- 数据集使用遵守各数据源的许可协议（标注引用），优先选择 CC 类或明确可学习用途的公开数据；
- 自采图像为本团队成果，可自由使用；用户上传图片**不得擅自用于模型训练**。

### 7.3 图片数据与隐私合规

- 用户上传图片仅用于本次识别请求，前端完成后即清除，服务端不持久化原始图片（或明确保留期限并在隐私说明中告知）；
- 首次使用弹窗说明相机/相册/麦克风权限用途；
- 历史记录默认本地可见，提供"清除历史"能力；
- **合规底线（延续 2.3 节）**：非诊断、非处方、医疗免责声明、毒性药材分级强警示。
