# 自建模型训练入门指南（数据集收集 → 标注 → 训练 → 导出 ONNX）

> 面向零机器学习经验的项目成员。目标：为「多模态中草药图像识别智能体」的自建识别模型主通道（本地模型）提供一套可执行、可复现的入门流程，最终产出一个 **ONNX 模型文件 + 类别清单**，填入后端配置即可替换当前占位桩。

---

## 0. 前置认知（先读这一段）

- 当前后端 `LocalModelRecognizer` 是**占位桩(Stub)**：架构、接口、调度都已就绪，但推理内核不真正分析图片，未配置模型时会如实回退到百度/Mock，**不会虚标**。
- 你**只需要做两件事**：① 训练出一个 ONNX 模型文件；② 提供配套类别清单。然后把两个文件路径填进 `.env`，主通道即可启用，**无需再改任何代码**。
- 训练本质：给电脑看大量"这是什么药材"的示例图片，让它学到规律。这需要**数据**、**算力**和**耐心**，是渐进过程。

---

## 1. 数据集收集（最花时间，最重要）

模型效果的上限由数据决定。宁可类别少而精，也不要类别多而糙。

### 1.1 选类别

- 首批建议 **10~20 种**（PRD 提到首批 50–100 种，但入门从少开始更稳）。
- 优先选**差异明显**、且知识库里已有的药材（如黄芪、甘草、金银花），便于直接验证。
- 与知识库 `herbs` 表里的 `name` 保持一致，识别结果才能命中详情。

### 1.2 每个类别需要多少图

| 阶段 | 每类图片量 | 说明 |
| --- | --- | --- |
| 入门/演示 | 每类 100~300 张 | 可训练出能演示的模型 |
| 初步可用 | 每类 500~1000 张 | 覆盖拍摄角度、光线、干燥/鲜品差异 |
| 较稳健 | 每类 2000+ | 面向真实生产 |

### 1.3 图片质量要求

- 尽量**白底或单一背景**、主体居中的正面图（与 App 拍摄场景接近）。
- 覆盖**干燥药材 + 饮片**（项目差异化点），每类最好含两种形态。
- 单张 ≤1MB，`.jpg/.png` 均可。
- 图片文件名建议带类别前缀，如 `黄芪_001.jpg`，便于核对。

### 1.4 公开数据源（注意版权与许可协议）

| 来源 | 说明 | 提示 |
| --- | --- | --- |
| [中国植物图像库 (PPBC)](https://ppbc.iplant.cn/) | 海量植物/药材照片 | 需遵守其使用条款，标注来源 |
| [植物智 iPlant](https://www.iplant.cn/) | 权威植物学数据平台 | 引用需合规 |
| [Kaggle 药材/植物数据集](https://www.kaggle.com/datasets) | 搜 "herb" / "chinese medicine" / "plant" | 下载时注意每套数据集的 License |
| 自行拍摄 | 手机实拍干燥药材/饮片 | 最贴合 App 场景，版权清晰 |

> 合规红线（对齐项目宪章）：数据集必须遵守许可协议；《中国药典》等内容只引用摘要并标注来源，不整本复制；用户上传图片不得擅自用于模型训练。

## 2. 数据标注与整理

本项目是**单标签图像分类**，标注很简单——**把图片按类别放进对应文件夹**即可，文件夹名就是标签。

```
data/
├── train/
│   ├── 黄芪/  黄芪_001.jpg 黄芪_002.jpg ...
│   ├── 附子/  附子_001.jpg ...
│   └── 甘草/  ...
└── val/       # 验证集（每类抽 10~20%），结构与 train 相同
    ├── 黄芪/  ...
    └── 附子/  ...
```

- **train**：训练用。
- **val**：训练时实时评估、防过拟合用，不与训练混用。
- 每类在 train/val 都要有，尽量按 8:2 或 9:1 拆分。
- 检查并删除：重复图、模糊图、拍错主体的图、带水印遮挡的图。

## 4. 训练（最小可运行示例）

用预训练的 ResNet18 做迁移学习，替换最后一层分类头，类别数 = 你的药材类别数。

```python
import os
from pathlib import Path
import torch
import torch.nn as nn
import torch.optim as optim
from torchvision import datasets, transforms, models

DATA_ROOT = "data"          # 内含 train/ 与 val/
NUM_CLASSES = len([d for d in os.listdir(f"{DATA_ROOT}/train") if os.path.isdir(f"{DATA_ROOT}/train/{d}")])
BATCH_SIZE = 32
EPOCHS = 20
DEVICE = "cuda" if torch.cuda.is_available() else "cpu"

transform = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.RandomHorizontalFlip(),      # 训练增强
    transforms.ToTensor(),
    transforms.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225]),
])

train_set = datasets.ImageFolder(f"{DATA_ROOT}/train", transform=transform)
val_set = datasets.ImageFolder(f"{DATA_ROOT}/val", transform=transform)
train_loader = torch.utils.data.DataLoader(train_set, batch_size=BATCH_SIZE, shuffle=True)
val_loader = torch.utils.data.DataLoader(val_set, batch_size=BATCH_SIZE)

# 迁移学习：加载预训练 ResNet18，替换分类头
model = models.resnet18(weights=models.ResNet18_Weights.IMAGENET1K_V1)
model.fc = nn.Linear(model.fc.in_features, NUM_CLASSES)
model.to(DEVICE)
# 冻结骨干网络，只微调最后一层，可加快且更稳
for p in list(model.parameters())[:-2]:
    p.requires_grad = False

criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(filter(lambda p: p.requires_grad, model.parameters()), lr=1e-3)

for epoch in range(EPOCHS):
    model.train()
    total, correct = 0, 0
    for images, labels in train_loader:
        images, labels = images.to(DEVICE), labels.to(DEVICE)
        optimizer.zero_grad()
        out = model(images)
        loss = criterion(out, labels)
        loss.backward()
        optimizer.step()
        total += labels.size(0)
        correct += (out.argmax(1) == labels).sum().item()
    print(f"epoch {epoch+1}: train acc = {correct/total:.3f}")

# 保存 PyTorch 权重（备份用）
os.makedirs("models", exist_ok=True)
torch.save(model.state_dict(), "models/herb_model.pt")
# 同时保存类别清单（顺序必须与 ImageFolder 的类别顺序一致！）
labels = sorted(train_set.classes) if not train_set.classes else train_set.classes
with open("models/labels.txt", "w", encoding="utf-8") as f:
    f.write("\n".join(labels))
print("labels:", labels)
```

**关键**：`labels.txt` 的**顺序**必须与模型分类头的输出索引一一对应。上面用 `train_set.classes` 生成，天然一致。

## 5. 导出 ONNX

ONNX 是通用交换格式，后端用 `onnxruntime` 加载，无需安装 torch，部署更轻。

```python
import torch
from torchvision import models

model = models.resnet18()
model.fc = torch.nn.Linear(model.fc.in_features, NUM_CLASSES)  # 与训练时一致
model.load_state_dict(torch.load("models/herb_model.pt", map_location="cpu"))
model.eval()

dummy = torch.randn(1, 3, 224, 224)  # 与预处理 Resize((224,224)) 一致
torch.onnx.export(
    model, dummy, "models/herb_model.onnx",
    input_names=["input"], output_names=["output"],
    dynamic_axes={"input": {0: "batch"}, "output": {0: "batch"}},
    opset_version=13,
)
print("ONNX exported.")
```

## 6. 接入项目（替换占位桩）

1. 把 `herb_model.onnx` 和 `labels.txt` 放到后端某目录，例如 `backend/models/`。
2. 编辑 `backend/.env`：

```bash
# ==== 本地自建模型（主通道）配置 ====
MODEL_ENABLED=true
MODEL_PATH=./models/herb_model.onnx
MODEL_LABELS=./models/labels.txt
MODEL_CONFIDENCE_THRESHOLD=0.6
MODEL_TOP_K=5
```

3. 修改 `backend/app/services/recognizer.py` 中 `LocalModelRecognizer._infer_topk` 的占位桩实现，替换为真实 onnxruntime 推理：

```python
import onnxruntime as ort
import numpy as np

def _infer_topk(self, image_bytes: bytes, k: int, labels: list[str]) -> list[tuple[str, float]]:
    # 1) 惰性加载 session（避免每次请求重复加载）
    if self._session is None:
        self._session = ort.InferenceSession(settings.model_path)
    # 2) 图像预处理：解码 + Resize(224,224) + 归一化 + HWC→CHW，返回 (1,3,224,224) float32
    img = self._preprocess(image_bytes)  # 需用 Pillow/numpy 实现，见下方说明
    # 3) 推理
    out = self._session.run(["output"], {"input": img})[0]  # (1, C)
    probs = np.exp(out - out.max(axis=1, keepdims=True))
    probs /= probs.sum(axis=1, keepdims=True)               # softmax
    topk_idx = probs[0].argsort()[::-1][:k]
    return [(labels[i], float(probs[0][i])) for i in topk_idx]
```

4. 完善 `_preprocess`（用 Pillow/numpy）：

```python
from PIL import Image

@staticmethod
def _preprocess(image_bytes: bytes) -> Any:
    from io import BytesIO
    img = Image.open(BytesIO(image_bytes)).convert("RGB").resize((224, 224))
    arr = np.asarray(img, dtype=np.float32) / 255.0
    mean = np.array([0.485, 0.456, 0.406], dtype=np.float32)
    std = np.array([0.229, 0.224, 0.225], dtype=np.float32)
    arr = (arr - mean) / std
    arr = arr.transpose(2, 0, 1)[None]  # HWC → 1CHW
    return arr
```

5. 后端需安装 `onnxruntime`、`pillow`、`numpy`（加入 `requirements.txt`）。
6. 重启后端，主通道即生效。识别时 channel 将显示 `local`；若置信度低于 `MODEL_CONFIDENCE_THRESHOLD`，前端会展示"相似品种 + 引导重拍"降级视图。

## 7. 常见问题

- **准确率低**：数据太少/太杂 → 增加每类图片、统一背景；或解冻更多层微调、增加 EPOCHS。
- **过拟合（train 高、val 低）**：减少 EPOCHS、加数据增强、增大数据量。
- **类别顺序错乱导致识别错**：务必用 `train_set.classes` 生成 labels.txt，且导出 ONNX 前加载的模型分类头类别数一致。
- **CPU 很慢**：减小 BATCH_SIZE、用 ResNet18 而不是更深的网络。
- **不虚标原则**：若模型效果不佳，宁可 `MODEL_ENABLED=false` 走百度/Mock，也不要让不靠谱的本地结果误导用户。
